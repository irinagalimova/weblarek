# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Классы и методы 
### Products - каталог товаров
Класс содержит следующие данные: 
1) `items` - хранит массив всех товаров;
2) `selectedItem` - хранит товар, выбранный для подробного отображения. 

Содержит методы: 
1) сеттер `setItems()` — сохранение массива товаров полученного в параметрах метода;
2) геттер `getItems()` — получение массива товаров из модели;
3) геттер `getProductByID()` — получение одного товара по его id;
4) сеттер `setSelectedProduct()` — сохранение товара для подробного отображения;
5) геттер `getSelectedProduct()` — получение товара для подробного отображения. 

### ShoppingcCart - корзина

Класс содержит следующие данные:
1) `items` - хранит массив всех товаров;

Содержит методы:

1) `getItems()` - получение массива товаров, которые находятся в корзине;
2) `addItem()` - добавление товара, который был получен в параметре, в массив корзины;
3) `removeItem()` - удаление товара, полученного в параметре из массива корзины;
4) `clearShoppingCart()` - очистка корзины;
5) `getTotalSum()` - получение стоимости всех товаров в корзине;
6) `getAmountOfItem()` - получение количества товаров в корзине;
7) `hasItem()` - проверка наличия товара в корзине по его id, полученного в параметр метода.

### Buyer - покупатель

Класс содержит следующие данные:
1) `payment` - вид оплаты;
2) `address` - адреc;
3) `phone` - телефон;
4) `email` - email.

Методы:

1) `setPayment()`, `setAddress()`, `setEmail()`, `setPhone()` - сохранение данных в модели;
2) `getData()` - получение всех данных покупателя;
3) `clearData()` - очистка данных покупателя;
4) `validate()` - валидация данных. Поле является валидным, если оно не пустое. Метод валидации даёт возможность определить не только валидность каждого отдельного поля, но и предоставлять информацию об ошибке, связанной с проверкой конкретного значения.

## Слой коммуникации

1) Класс `AppApi` отвечает за взаимодействие с сервером. В конструктор он принимает объект класса `Api` (композиция), а в методах использует его возможности для отправки запросов.
2) Метод `getProducts()` выполняет GET-запрос на эндпоинт /product и возвращает объект с массивом товаров (`IProductsResponse`).
3) Метод `postOrder(data: IOrderData)` выполняет POST-запрос на эндпоинт /order и отправляет данные о покупателе и выбранных товарах. Формат данных соответствует коллекции Postman.
4) В файле src/types/index.ts описаны типы для данных, которые приложение получает от сервера и отправляет на него:

`IProductsResponse` — ответ с сервера при запросе товаров;
`IOrderData` — данные для отправки заказа;
`IOrderResponse` — ответ сервера после создания заказа.
5) При создании новых типов используются уже существующие (`IProduct`, `IBuyer`), чтобы избежать дублирования.

### Пример использования в main.ts
```
const api = new Api(API_URL);
const appApi = new AppApi(api);

appApi.getProducts()
    .then(data => console.log(data.items))
    .catch(error => console.error(error));
```

## Слой представления (View)

Все классы используют render(data) из Component.  Он передаёт данные в сеттеры и возвращает контейнер. Без аргументов render() возвращает ту же разметку.

### Header

Шапка сайта и счётчик корзины.

Конструктор: `constructor(events: IEvents, container: HTMLElement)`.

Поля:

- `counterElement: HTMLElement` - элемент, отображающий количество товаров в корзине;
- `basketButton: HTMLButtonElement` - кнопка, по нажатию на которую создаётся событие открытия корзины.;
Интерфейс IHeader:

- `counter: number` - количество товаров в корзине;
Методы класса:

- `set counter(value: number)` - устанавливает количество товаров в счётчике корзины;
Кнопка корзины вызывает basket:open.

### Gallery

Каталог карточек на главной странице.

Методы класса:

- `set catalog(items: HTMLElement[])` - заменяет содержимое галереи переданными карточками;

### Card 

Родительский класс для трех карточек: CardCatalog, CardPreview, CardBasket. В этот класс вынесен общий для всех дочерних классов функционал: содержит название и цену. 

Поля класса: 

- `titleElement: HTMLElement` - элемент с названием товара;
- `priceElement: HTMLElement` - элемент с ценой товара;

Методы класса:

- `set title(value: string)` - устанавливает название товара;
- `set price(value: number | null)` - устанавливает цену или текст «Бесценно». 


### CardCatalog

Карточка товара в каталоге.

Поля класса:

- `imageElement: HTMLImageElement` - изображение товара;
- `categoryElement: HTMLElement` - элемент с названием категории товара;

Методы класса: 

- `set title(value: string)` - устанавливает название товара и альтернативный текст изображения;
- `set image(value: string)` - устанавливает адрес изображения товара;
- `set category(value: string)` - устанавливает название категории и её CSS-класс;

Поля названия и цены, сеттер цены наследуются от Card.

Клик по карточке вызывает actions.onClick. В Презентере этот обработчик генерирует card:select.

### CardPreview

Карточка товара с описанием, которая открывается при клике на карточку в каталоге.

Поля:

- `imageElement: HTMLImageElement` - изображение товара;
- `categoryElement: HTMLElement` - элемент с названием категории товара;
- `descriptionElement: HTMLElement` - элемент с описанием товара;
- `buttonElement: HTMLButtonElement` - кнопка покупки или удаления товара;

Методы класса:

- `set title(value: string)` - устанавливает название товара и альтернативный текст изображения;
- `set image(value: string)` - устанавливает адрес изображения товара;
- `set category(value: string)` - устанавливает название категории и её CSS-класс;
- `set description(value: string)` - устанавливает описание товара;
- `set buttonText(value: string)` - меняет надпись на кнопке;
- `set buttonDisabled(value: boolean)` - включает или отключает блокировку кнопки;

Поля названия и цены, сеттер цены наследуются от Card.

Надпись и доступность кнопки передаёт Презентер. Кнопка вызывает `actions.onClick`, который генерирует `preview:submit`.

### CardBasket

Карточка товара в корзине.

Поля:

- `indexElement: HTMLElement` - элемент с номером товара в корзине;
- `deleteButton: HTMLButtonElement` - кнопка удаления товара из корзины;

Методы класса:

- `set index(value: number)` - устанавливает номер строки в корзине;
Поля названия и цены, сеттер цены наследуются от Card.

Кнопка удаления вызывает `actions.onClick`. Презентер передаёт обработчик события `basket:delete` с id товара.

### Basket

Корзина товаров.

Поля:

- `listElement: HTMLElement` - список, в который вставляются карточки товаров;
- `totalElement: HTMLElement` - элемент с общей стоимостью товаров в корзине;
- `orderButton: HTMLButtonElement` - конпка перехода к оформлению заказа;

Методы класса:

- `set items(value: HTMLElement[])` - вставляет строки товаров или сообщение «Корзина пуста»;
- `set total(value: number)` - устанавливает общую стоимость товаров;
- `set buttonDisabled(value: boolean)` - включает или отключает блокировку кнопки. 

Пустой список показывает «Корзина пуста». Кнопка оформления вызывает `order:open`. Сумму и доступность кнопки передаёт Презентер.

### Modal

Оболочка модального окна, в нее вставляется контент из template. 

Поля:

- `closeButton: HTMLButtonElement` - кнопка закрытия модального окна;
- `contentElement: HTMLElement` - элемент для содержимого модального окна;

Методы класса:

- `set content(value: HTMLElement)` - заменяет содержимое модального окна;
- `open(): void` - открывает окно, добавляя класс modal_active;
- `close(): void` - закрывает окно, убирая класс modal_active.

Сеттер `content` вставляет готовый компонент. Крестик и фон вызывают `modal:close`, внутренний клик не закрывает окно. От `Modal` другие классы не наследуются.

### Form

Родительский класс для двух карточек: Order, Contacts. В этот класс вынесен общий для всех дочерних классов функционал: кнопка отправки формы и элемент для сообщений об оибке. 

Поля:

- `submitButton: HTMLButtonElement` - кнопка отправки формы;
- `errorsElement: HTMLElement` - элемент для сообщений об ошибках;

Методы класса:

- `set valid(value: boolean)` - делает кнопку отправки доступной, если ошибок нет;
- `set errors(value: string)` - выводит сообщения об ошибках формы;
Сеттер `valid` управляет кнопкой отправки, `errors` показывает текст ошибок. События называются по атрибуту `name` формы: `order:change`, `order:submit`, `contacts:change`, `contacts:submit`. При вводе передаются имя поля и значение. Отправка отменяет стандартное действие браузера. Проверку данных выполняет модель.

### Order 

Первая форма: оплата и адрес.

Поля:

- `cardButton: HTMLButtonElement` - кнопка выбора онлайн-оплаты;
- `cashButton: HTMLButtonElement` - кнопка выбора оплаты при получении;
- `addressInput: HTMLInputElement` - поле ввода адреса доставки;

Методы класса:

- `set payment(value: TPayment | null)` - выделяет выбранный способ оплаты или снимает выделение;
- `set address(value: string)` - устанавливает значение поля адреса;

### Contacts 

Вторая форма: почта и телефон. 

Поля:

- `emailInput: HTMLInputElement` - поле ввода почты покупателя;
- `phoneInput: HTMLInputElement` - поле ввода телефона покупателя;

Методы класса:

- `set email(value: string)` - устанавливает значение поля почты;
- `set phone(value: string)` - устанавливает значение поля телефона;

Слушатели ввода и отправки, а также сеттеры ошибок и доступности кнопки наследуются от Form.

### Success 

Сообщение об успешном заказе.

Поля:

- `descriptionElement: HTMLElement` - элемент с сообщением о списанной сумме;
- `closeButton: HTMLButtonElement` - кнопка, вызывающая событие завершения покупки;

Методы класса:

- `set total(value: number)` - показывает сумму списания после успешного заказа;
Сеттер `total` показывает списанную сумму. Кнопка завершения вызывает `success:close`.

## События

События моделей вызываются после сохранения данных. Презентер получает актуальные данные через методы моделей и обновляет интерфейс.

- `catalog:changed` — Products.setItems сохранил каталог.
- `product:changed` — Products.setSelectedProduct изменил выбранный товар.
- `basket:changed` — ShoppingCart добавил, удалил товар или очистил корзину.
- `buyer:changed` — Buyer изменил поле или очистил данные.
- `card:select` — Клик по карточке каталога, передаётся `IProduct`.
- `preview:submit` — Клик по кнопке подробной карточки, без данных.
- `basket:open` — Клик по корзине в шапке.
- `basket:delete` — Удаление строки корзины, `{ id: string }`.
- `order:open` — Кнопка «Оформить».
- `payment:change` — Выбор оплаты, `{ payment: TPayment }`.
- `order:change` — Ввод адреса, `{ field: string, value: string }`.
- `order:submit` — Отправка первой формы.
- `contacts:change` — Ввод почты или телефона, `{ field: string, value: string }`.
- `contacts:submit` — Отправка второй формы.
- `modal:close` — Клик по крестику или фону.
- `success:close` — Кнопка на экране успеха.

В `main.ts` также есть обработчик `modal:open`, но сейчас компоненты это событие не вызывают. При открытии экранов Презентер вызывает `modal.open()` напрямую.

## Презентер

Написан в `src/main.ts`, отдельного класса нет. В начале создаются модели, брокер событий и компоненты, затем идут обработчики. После подписок выполняется запрос каталога.

Вспомогательные функции:

- `getBasketCards(): HTMLElement[]` — создаёт разметку строк корзины с номерами и обработчиками удаления.
- `updateOrderForm(): void` — передаёт данные покупателя и ошибки оплаты и адреса в Order.
- `updateContactsForm(): void` — передаёт контакты и ошибки почты и телефона в Contacts.

Как работает приложение:

1. `appApi.getProducts()` получает товары, `productsModel.setItems()` сохраняет их. На `catalog:changed` создаются карточки и передаются в Gallery.
2. Клик сохраняет выбранный товар в модели. На `product:changed` открывается подробная карточка. Презентер выбирает надпись кнопки: «Купить», «Удалить из корзины» или «Недоступно».
3. `preview:submit` добавляет или удаляет выбранный товар и закрывает окно. Товар с ценой `null` купить нельзя.
4. `basket:changed` обновляет список, сумму и счётчик. Удаление через `basket:delete` оставляет корзину открытой. В пустой корзине оформление недоступно.
5. Ввод в формах сохраняется методами Buyer. `buyer:changed` обновляет обе формы. На каждом шаге показываются только его ошибки.
6. `order:submit` проверяет первый шаг и открывает Contacts. `contacts:submit` проверяет все поля и непустую корзину, собирает `IOrderData` и вызывает `appApi.postOrder()`.
7. После успешного ответа очищаются корзина и покупатель, открывается Success с суммой из ответа. При ошибке данные остаются, сообщение выводится через `window.alert`, подробности — в консоль.

Переменная `isOrderSending` не даёт отправить ещё один заказ, пока выполняется предыдущий запрос. В `finally` она возвращается в `false`.

После изменений моделей отображение обновляется в обработчиках их событий. Также данные передаются компонентам при открытии модального окна. Блокировку прокрутки страницы обеспечивает CSS-правило `.page:has(.modal_active)`.
